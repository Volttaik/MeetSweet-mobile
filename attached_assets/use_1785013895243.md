# MeetSweet API — Agent Usage Guide

This document describes every API endpoint in the MeetSweet backend. Use it as the authoritative reference for calling any route.

---

## Core Conventions

### Base URL
All routes are prefixed with `/api/`. During local development the server runs at `http://localhost:3000`.

### Authentication
Protected routes require a Bearer token in the `Authorization` header:
```
Authorization: Bearer <access_token>
```
Access tokens are short-lived JWTs. Use `POST /api/auth/refresh` to rotate them with a refresh token.

### Response Envelope
Every response uses this envelope:

**Success:**
```json
{ "ok": true, "data": { ... }, "message": "optional string" }
```

**Error:**
```json
{ "ok": false, "error": "human-readable message", "code": "ERROR_CODE" }
```

### Common HTTP Status Codes
| Code | Meaning |
|------|---------|
| 200 | OK |
| 201 | Created |
| 400 | Bad request / validation error |
| 401 | Missing or invalid auth token |
| 403 | Authenticated but not authorized |
| 404 | Resource not found |
| 409 | Conflict (duplicate) |
| 500 | Server error |

## 1. Auth & Account

### `POST /api/auth/register`
**Auth:** None  
Register a new user. Sends a verification email.

**Body:**
```json
{
  "full_name": "string (required)",
  "username":  "string (required, will be lowercased)",
  "email":     "string (required, will be lowercased)",
  "password":  "string (required)",
  "phone":     "string (optional)"
}
```

**Success (201):**
```json
{ "ok": true, "data": { "user_id": "uuid" }, "message": "Registration successful. Please verify your email." }
```

**Errors:**
- `409` — Email already registered
- `409` — Username already taken

---

### `POST /api/auth/login`
**Auth:** None  
Log in with email and password.

**Body:**
```json
{
  "email":     "string (required)",
  "password":  "string (required)",
  "device_id": "string (optional)"
}
```

**Success (200):**
```json
{
  "ok": true,
  "data": {
    "access_token":  "string",
    "refresh_token": "string",
    "user": {
      "id": "uuid",
      "full_name": "string",
      "username": "string",
      "email": "string",
      "is_creator": false,
      "is_verified": false,
      "role": "user | creator | admin"
    }
  }
}
```

**Errors:**
- `401` — Invalid credentials
- `403` — Email not verified

---

**Success (200):**

```json
  "data": {
    "database": "connected | error",
    "env": { ...presence flags for each required env var... }
  }
}
```

---

### `GET /api/cron/daily`
**Auth:** None — must include `Authorization: Bearer <CRON_SECRET>` header  
Triggered daily by the scheduler (Vercel Cron or equivalent). Runs maintenance tasks:

1. Expire posts past their `expires_at`
2. Expire lapsed subscriptions
3. Delete expired/used verification codes
4. Delete expired sessions
5. Delete expired/revoked refresh tokens

**Success (200):**
```json
{
  "success": true,
  "tasksCompleted": ["expirePosts (updated: 0)", "..."],
  "tasksFailed": [],
  "executionTime": 123
}
```

> Note: The `CRON_SECRET` env var must be set. Pass it as `Authorization: Bearer <value>`.
